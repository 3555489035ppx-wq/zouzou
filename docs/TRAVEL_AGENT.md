# 走走旅行助手第一版（开发分支，未上线）

## 实现范围
- 独立演示页 /agent-demo，单独聊天界面，内含知识库问答、攻略卡片和每日行程；不使用原AppShell、不添加任何现有产品入口。
- POST /api/agent/chat 接受当前页面的多轮对话。
- 单次模型调用选择澄清、知识库推荐或计划生成，随后执行服务端受限工具。
- “上海哪里好玩”直接返回有来源的知识卡片，不强迫填预算和日期。
- “上海两天一晚，白天少走路，晚上喜欢吹风散步”解析为低步行偏好及夜间户外偏好。
- 真正矛盾或信息不足时追问；无知识、未通过排程检查时明确返回不足，不编造成功。
- 生成器只接收服务端知识库。没有任意代码执行、网页浏览或订票工具。
- 这是一版受限工具编排助手，不是任意自主执行系统；问答目前使用检索摘要，尚未做开放式多步检索和自由事实推断。
- 多轮输入支持重新解释偏好并重生成；不保证修改一个日期时其他日期逐像素/逐地点锁定。
- 来源仅代表资料出处，不等于已验证的实时营业、交通或天气。
- 页面展示服务端实际完成的阶段，不伪造实时推理过程。

## 使用与配置
复用服务端 AI_PROVIDER 与相应的 OPENAI_API_KEY / DEEPSEEK_API_KEY、模型名称配置，密钥只能放在服务端，禁止 VITE_ 前缀密钥。
现有云端知识发布闸门继续生效：KNOWLEDGE_RELEASE_APPROVED 必须已有批准，KNOWLEDGE_VERSION 必须有效。不得为演示绕过闸门。
本地 Node 和 Cloudflare 接口均有路由。Cloudflare 继续使用既有会话、CSRF 和 AI 速率限制。每轮最多一次模型调用；会消耗所配置供应商额度。
未代填或读取任何密钥，未调用真实付费模型，未部署。

## 数据与交互边界
对话仅保存在当前 React 页面内存，刷新或离开会清除。发送时对话交由已配置模型供应商处理；页面已提示。
最多20条消息、合计16000字；超限明确提示，不静默截断用户历史约束。
停止、离开页面会中止客户端请求，迟到响应不会覆盖新的结果。服务端总超时40秒，前端45秒。
失败保留输入和旧结果，可手动重试。新对话需确认，仅清当前页面内存。
不自动保存/上传行程，不修改原草稿、已保存行程、账号、知识库或小程序。
新对话历史保留方案摘要，便于指代；重新生成不修改用户已经保存的历史行程。

## 必须验收
1. 上海哪里好玩：有来源，未生成强制行程
2. 上海两天一晚 + 夜间吹风散步：天数、晚数正确，至少有晚间户外候选
3. 不走路 + 夜间走路：先澄清；确认白天少走后正常规划
4. 多轮保留城市/天数/饮食禁忌，最新明确更正优先
5. 城市缺库、没有符合条件方案、模型失败、超时均不冒充成功
6. 快速连点、停止后重发、离开页面、超长对话不产生旧响应覆盖
7. 原首页、表单、个人行程仍正常；不覆盖本地数据

## 加固迭代（2026-10-06）
- 预算默认可选，不追问、不限制，也不作为缺失信息拦截；用户主动给出预算才检查。
- 成功返回攻略后，可在卡片末尾亲切询问一次大概预算；忽略或拒绝不影响使用，不重复追问。
- 按有效用户意图独立重新校验生成结果，不信任缓存validation.passed；检查城市、天数、晚数、人数、日期、占位地点与夜间户外依据。
- 夜間散步依据知识卡片名称/标签；仍不是实时天气、开放时间或无障碍认证。
- 白天少走/晚间散步模式下，超过15分钟的白天步行转场会被拦截。15分钟是本Demo的策略阈值，不代表用户明确承诺或真实路况。
- 修复过敏词被当作正则表达式执行的风险，使用字面匹配；过敏安全仍需商家确认。
- 对话校验要求用户/助手交替，不接受system角色；对话状态仅当前页面持有，服务端不建立跨用户共享对话缓存。
- 服务端生成请求编号，错误可追踪；运行日志仅记录编号和耗时，不记录对话、位置、邮箱或密钥。
- 限制模型与接口响应大小；前端流读取有长度检查、取消与释放；不自动重试产生额外模型费用。
- 云端复用现有D1会话/速率限制；本地开发接口新增每分钟20次、同时2个请求的进程级上限，不冒充多机分布式配额。
- 所有代码仍仅在开发分支。上述为已编写机制，未做运行验证，不能宣称达到企业生产标准。
