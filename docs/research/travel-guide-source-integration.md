# 走走｜旅行攻略来源与合规接入研究

研究日期：2026-08-29

## 结论

可以参考小红书等平台的旅行攻略，但应把它们当作“用户体验线索”和“候选地点来源”，不能直接当作营业时间、价格、路程、库存或预约结果。真实行程仍必须用官方地点信息、地图路线和天气数据复核。

最适合走走的接入顺序是：

1. 用户主动粘贴公开攻略链接、上传攻略截图或复制文字；走走只解析用户提交的内容，并保留原链接。
2. 从攻略中抽取 `GuideCandidate`，例如地点名、玩法、适合时段、避坑提示和原文证据。
3. 用高德/其他有授权的 POI、路线和天气接口复核候选地点。
4. 在用户确认后才放入 `TripIntent` 和排程器；没有复核的内容只能显示为“攻略线索/待确认”。

不建议通过模拟登录、绕过验证码、批量抓取小红书页面或复制发布者的完整文字/图片来构建内容库。这种做法不稳定，也会带来平台规则、个人信息和著作权风险。

## 平台核查

### 小红书

- 小红书开放平台当前官方 API 参考页公开的接口目录主要是 OAuth 授权、Token、用户基本信息和解除授权等能力；页面没有把“按关键词搜索公开旅行笔记并批量读取全文”列为通用接口。见：[小红书开放平台 API 参考](https://openaccount.xiaohongshu.com/docs/api-reference)。
- 官方快速接入文档描述的是“用户点击、授权、返回应用、获取用户信息”的流程，不是攻略内容搜索接口。见：[小红书开放平台快速接入](https://openaccount.xiaohongshu.com/docs/quick-start)。
- 小红书官方社区公约要求借鉴或转载时核实来源，转载应取得对方同意并注明出处；官方侵权平台也明确保护文字、图片等权利。因此走走应优先保存链接和短摘要，不应复制整篇笔记或图片。见：[小红书社区公约](https://pgy.xiaohongshu.com/help/detail?id=1eda0a065dd894063c2e029a49e8f6a1&userType=4)、[小红书权利保护中心](https://ipp.xiaohongshu.com/)。
- 小红书分享开放平台更适合把走走生成的内容分享回小红书，而不是读取全站攻略。见：[小红书分享开放平台](https://agora.xiaohongshu.com/)。

结论：小红书可以作为“用户主动导入的攻略来源”，或者在取得官方合作/明确授权后接入；当前不应实现无授权的后台爬虫。

### 携程及交易型平台

- 携程曾公开介绍旅游开放平台，覆盖内容导入/分销以及门票、玩乐、租车、接送机等交易接口，但这是供应商/分销商合作模式，不等于任何应用都可以读取携程社区攻略。见：[携程旅游开放平台公告](https://ttdopen.ctrip.com/apiplatform/help-detail.do?no=88)。
- 携程商旅也提供独立的开发者平台和接口调试流程，面向企业差旅合作场景。见：[携程商旅开发者平台](https://openapi.ctripbiz.com/)。

结论：携程适合作为获得授权后的酒店、门票、活动和订单事实源；攻略内容仍需按具体合作范围接入。

### 大众点评/本地生活平台

当前没有在本次核查中确认到可供走走直接使用的、公开且面向普通开发者的“全量攻略/评论搜索 API”。因此不应把网页抓取当作默认方案。若未来拿到正式合作接口，可把商家营业状态、地址、价格区间和用户评价摘要分别建模，并保留平台来源和更新时间。

## 推荐的数据结构

攻略线索不能直接复用 `MediaFact`，建议单独建立：

```ts
type GuideCandidate = {
  id: string
  platform: 'xiaohongshu' | 'ctrip' | 'dianping' | 'user-import' | 'licensed-search'
  sourceUrl: string
  title: string
  author?: string
  publishedAt?: string
  fetchedAt: string
  excerpt: string
  claims: Array<{
    type: 'place' | 'activity' | 'tip' | 'price' | 'opening' | 'route'
    text: string
    placeName?: string
    confidence: number
    verified: boolean
  }>
  permission: 'user-provided' | 'licensed' | 'unknown'
}
```

排程器只允许 `verified: true` 的营业时间、路线、价格和预约信息成为硬事实；未验证内容可以用于推荐排序，但必须显示“来自攻略，出行前复核”。

## 对走走的实现建议

第一版先做“粘贴链接/上传攻略截图”而不是爬虫：

- 前端增加攻略链接输入和来源平台选择。
- 服务端只接受用户主动提交的 URL/截图，生成 `GuideCandidate`，限制长度、数量和缓存时间。
- LLM 只提取地点和体验描述，不提取为确定价格或营业状态。
- 通过 POI 服务做地点消歧，通过路线/天气服务做事实复核。
- 结果展示三种标签：`用户原话`、`攻略线索`、`已验证事实`。
- 用户点击“加入行程”后才进入排程，并保留来源链接和撤销操作。

这样既能吸收小红书里的真实体验，也不会让一篇可能过期或带推广性质的笔记直接改变用户的行程。
