## 0. 结论先行（Phase 0 基线）

第一遍已从启动页开始，实际走过：启动 → 首页 → 城市切换（上海→杭州）→ 旅行输入 → 截图区域 → AI 理解 → 三方案 → 方案详情 → Day 2 → 时间轴/地图 → 地点替换 → 邀请朋友 → 投票 → 保存行程 → Day 1/Day 2 地图 → 继续行程/到达 → 社区双列 → 社区卡片 → 我的 → 收藏/喜欢 → 设置开关。

以下结论是修改前的基线，不是对执行后版本的判断。Phase 0 发现的 P0 集中在：

1. 展示壳首次打开直接进入首页，跳过登录；启动品牌图形不是用户指定源资产。
2. 全局城市状态与已生成行程存在语义错配（切到杭州后仍显示武康路，保存上海方案后行程头部变成杭州）。
3. 社区卡片仍强制进入路线回放，详情、点赞、评论、使用行程的路径不符合消费级内容社区预期。
4. 我的页面 Cover 没有 Full Bleed 到状态栏，多个 Grid 项目仍把用户带进强制回放。
5. 行程地图虽然已降噪，但没有在“继续行程”时只 Fit 当前两点；Bot 表现仍像单一黑色状态，地图远程瓦片有首屏等待。
6. 固定底栏在首页/社区/我的的首屏会压住内容，底栏仍是带大圆角的漂浮卡片形态。

下表为第一遍真实结果。`修改后结果`在 Phase 0 明确写为“待执行/待回归”；第 6 节记录统一执行后的复验结论。

### 6.4 当前已知边界（不伪装成已解决）

1. 配置有效的高德 JS API key 和白名单后优先使用 AMap；未配置或网络受限时显示稳定的浅色本地矢量 fallback。它是可解释的降级，不是灰屏。
2. 远程 AI 仅用于文本意图提取；响应超时、空结果或结构无效时回退本地解析。真实生产仍需服务端密钥、配额和日志策略。
3. 酒店、餐饮、交通和门票金额是本地排程参考估算；详情明确提示实时价格与库存以第三方平台为准。
4. Cover 裁剪/撤销、真实定位授权、真实订单和公开发布仍属于后续产品化工作，不阻塞本地私人 Demo 的主链路验收。
