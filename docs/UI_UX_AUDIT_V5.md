## 逐步体验记录

### STEP 01｜打开 App / 首页

问题编号：P0-01、P0-02、P0-03、P0-07  
页面：首页与 iPhone 展示壳  
问题类型：Safe Area、状态栏、导航、Content Density  
当前问题：录屏首帧先显示一块空白内容；状态栏写出 `Wi‑Fi` 文本；首页城市、天气、头像和 Dynamic Island 的安全区关系不够可信；底部 Tab 固定在内容上方但长页面继续从 Tab 后面露出图片。  
为什么是问题：首屏会被识别为网页 Mockup；系统栏与业务内容没有形成独立层；用户无法判断当前页面是否加载完成，向下滚动时最后内容被遮挡。  
用户操作步骤：启动 → 等待首页 → 向下滚到最后。  
当前结果：首帧内容为空；首页随后出现；Tab 选中反馈存在，但行程仍是人物 Logo；导航下方可见图片泄漏。  
修改方案：建立独立 StatusBar / SafeAreaTop / NavigationArea / ContentArea / TabBar / SafeAreaBottom；状态栏只使用图形信号；启动显示与参考图一致的 2 秒走走 splash；所有可滚动页统一底部安全内边距；Tab 图标改为 Route。  
修改后的结果：打开即先显示稳定的走走品牌页，2 秒后进入首页；业务内容从安全区开始；滚动到末尾仍能完整看到最后一项；选中 Tab 立即变黑。  
用户预期：像真实 iPhone App，而不是网页套壳。  
优先级：P0

### STEP 02｜切换城市

问题编号：P0-08、P1-01  
页面：城市 Bottom Sheet  
问题类型：UX、Information Architecture、Spacing  
当前问题：Sheet 从底部打开，核心内容集中在下半屏；搜索、当前位置、热门城市之间的层级偏弱；当前位置是静态“未开启定位”文案。  
为什么是问题：轻量的城市切换被感知为重型弹窗；用户需要向下寻找热门城市；状态和动作没有区分。  
用户操作步骤：点击上海 → 点击杭州 → 再切回上海。  
当前结果：城市切换和首页推荐、行程标题、社区城市可以同步；Sheet 可关闭。  
修改方案：使用 Medium Sheet，打开后搜索与热门城市位于中上部；当前位置变为“开启定位”动作行；城市按钮统一高度和选中态；切换完成后关闭并更新全局 City Store。  
修改后的结果：杭州选择在一屏内完成，首页、社区、地图、天气和推荐内容全部同步。  
用户预期：选择一次，整个产品的城市上下文都变化。  
优先级：P0

### STEP 03｜旅行创建与输入

问题编号：P1-02、P1-03  
页面：创建旅行  
问题类型：Typography、Content Density、Interaction Feedback  
当前问题：四张截图默认存在，用户不容易理解它们是已添加还是示例；主按钮过重；页面下半部留白明显。  
为什么是问题：第一次使用者可能误以为已上传了自己的资料；主要任务“写需求”与“添加截图”的状态不够清楚。  
用户操作步骤：进入旅行 → 输入“上海三天两晚、预算 4000、武康路/安福路/展览/咖啡” → 确认截图 → 点击帮我看看。  
当前结果：输入计数正确；4 张截图显示；可以提交。  
修改方案：区分示例素材与用户素材；展示“已添加 4 张”并提供明确的添加/删除；主按钮遵守单一 Primary；压缩无意义底部留白。  
修改后的结果：用户知道 AI 将读取哪些资料，提交动作有明确反馈。  
用户预期：输入与素材状态透明。  
优先级：P1

### STEP 04｜AI 理解

问题编号：P0-09、P1-04、P1-05  
页面：理解旅行 / 生成方案  
问题类型：Motion、Bot、Typography、Content Density  
当前问题：理解完成与生成方案阶段使用不同的 Bot 形态（圆形、轨道三角形等）；处理页的留白虽然有沉浸意图，但状态转移缺少清晰节奏；完成后的内容卡在首屏下方被截断。  
为什么是问题：用户会认为是两个不同产品或随机生成的机器人；无法预期下一步何时出现。  
用户操作步骤：提交旅行需求 → 观察读取描述、截图、整理、检查、生成步骤 → 点击开始规划。  
当前结果：5 个步骤最终全勾选，能进入三方案；Bot 只展示一个静态/思考式表情。  
修改方案：统一 Bloub/Grok Bot 资产与状态机；Reading/Screenshot/Organizing/Validation/Planning 使用同一身体不同表情；状态列表用 Active/Done/Future 视觉区分；完成后使用短暂成功态再进入方案。  
修改后的结果：用户能理解当前状态，Bot 表情随状态变化且不遮挡内容。  
用户预期：AI 在工作，而不是页面卡住。  
优先级：P0

### STEP 05｜三方案轮播

问题编号：P1-06、P1-07  
页面：选择方案  
问题类型：Interaction Feedback、Content Density、Horizontal Scroll  
当前问题：录屏中出现桌面式横向滚动条与箭头；焦点卡、已选卡和主 CTA 的语义容易混淆；卡片下方存在较大片空白。  
为什么是问题：滚动条暴露实现细节；用户不知道“正在看”与“已选择”的区别；首屏信息密度不平衡。  
用户操作步骤：最匹配 → 横滑最轻松 → 横滑体验最丰富 → 回到最匹配 → 查看这套走法。  
当前结果：三个方案存在，点选状态可同步，当前实现已隐藏滚动条；横滑语义仍需量测。  
修改方案：Carousel 只露出 8–15% 相邻卡；焦点边框与 Selected Check 分离；仅当前焦点显示 Primary CTA；分页点实时同步；隐藏浏览器滚动条并保留触控滚动。  
修改后的结果：用户能明确知道当前浏览哪套、最终选哪套。  
用户预期：比较方案是连续、稳定、可预测的。  
优先级：P1

### STEP 06｜方案详情 / 替换 / 预算

问题编号：P0-10、P1-08、P1-09、P1-10  
页面：方案详情  
问题类型：Typography、Information Architecture、Content Density、第三方边界  
当前问题：每个地点默认同时出现锁定、替换、删除、更多四个操作；第三方说明仍是“本地原型不提供支付或实时库存”；预算和邀请入口需要向下滚动才能看见。  
为什么是问题：重复操作噪音压过路线信息；开发提示破坏消费级可信度；用户难以找到下一步。  
用户操作步骤：查看 Day 1 → 地图/时间轴 → 替换武康路 → 查看预算 → 邀请朋友。  
当前结果：替换面板可用，替换后显示“已保留原路线骨架”；预算可见；邀请可进入朋友页。  
修改方案：默认只显示“替换”和更多；更多 Action Sheet 承载锁定/调整时间/删除；第三方文案改为“最终价格和库存以第三方平台为准”；在详情底部明确预算摘要与下一步 CTA。  
修改后的结果：路线阅读优先，操作按需展开，预算和边界清晰。  
用户预期：像真实旅行规划工具，而不是调试面板。  
优先级：P0

### STEP 07｜邀请 / 投票 / 保存

问题编号：P0-11、P1-11  
页面：朋友、方案投票  
问题类型：Navigation、Safe Area、Interaction Feedback  
当前问题：录屏中朋友页底部主按钮贴近 Home Indicator，部分内容被截断；投票页的保存按钮虽可用，但缺少完成后的回到首页/行程反馈。  
为什么是问题：用户不能确认操作是否完成；底部内容被系统区域覆盖。  
用户操作步骤：模拟安安接受 → 进入方案投票 → 结束投票 → 保存行程。  
当前结果：投票数即时更新，保存后进入行程页。  
修改方案：所有非 Tab 页面统一 SafeAreaBottom；保存后给出短暂成功反馈并明确进入行程；按钮状态包含 Default/Pressed/Loading/Success。  
修改后的结果：用户知道“保存行程”已完成，并能继续下一步。  
用户预期：协作流程有闭环。  
优先级：P0

### STEP 08｜行程地图 / 开始 / 到达 / Day2

问题编号：P0-12、P0-13、P0-14、P0-15、P1-12  
页面：行程执行页  
问题类型：Map、Motion、Bot、Content Density、Safe Area  
当前问题：地图落到旧式 OSM fallback，标签密度高且风格旧；录屏中点击继续后地图短暂变空白并发生 Camera Jump；Bot 在地图上表现为单一黑色思考点；地图与“今日进度/今日行程”的层级冲突，列表末端仍会靠近 Tab；酒店费用显示 ¥0。  
为什么是问题：地图是执行页核心，加载闪烁和跳帧会削弱信任；Bot 无法表达行走/到达；用户看不到完整路线和实际花费。  
用户操作步骤：进入 Day1 → 点击继续行程 → 观察武康路→安福路 → 等待到达 → 切换 Day2。  
当前结果：按钮立即变为暂停；进度可从 1/7 变为 2/7；Day2 可切换；地图暂时显示真实路线，但样式旧，酒店 ¥0。  
修改方案：优先高德自定义浅色样式，未配置 Key 时使用现代低噪声 raster fallback；地图实例只初始化一次，Segment Start 只做一次 500–700ms fit；保持地图 DOM 不卸载；Bot 使用透明背景的多表情状态并沿路线插值移动；路线节点显示完成/当前/未开始；酒店使用合理本地参考价；今日行程预留完整底部安全间距。  
修改后的结果：点击后相机稳定聚焦当前与下一站，Bot 匀速移动、到达减速并弹出卡片，地图始终存在，费用不再为零。  
用户预期：像真实导航中的一段可执行行程。  
优先级：P0

### STEP 09｜社区列表 / 详情 / 点赞收藏 / 复用

问题编号：P0-16、P1-13、P1-14、P1-15  
页面：社区、社区回放、内容详情  
问题类型：Map、Navigation、Interaction Feedback、Content Density  
当前问题：录屏社区回放开始时地图加载慢并出现大面积空白；详情页顶部返回箭头偏小；“使用这个行程”固定按钮过大；详情正文没有像个人行程一样的具体地点/时间/费用清单。  
为什么是问题：用户无法快速判断路线内容；主 CTA 抢占视觉；社区内容不能直接被执行或比较。  
用户操作步骤：社区 → 打开一条卡片 → 等待回放 → 跳过/完成回放 → 点赞、收藏 → 使用这个行程。  
当前结果：回放最终可显示地图；点赞变红、收藏填充；复用打开选择面板；但详情缺少具体路线清单。  
修改方案：预加载地图并提供非空骨架/状态；返回按钮保持 44pt 命中区与 22pt 图标；主 CTA 缩为内容宽度的次要高度；新增“具体行程”列表（时间、地点、停留、预算、交通）；点赞/收藏使用 aria-pressed 与即时颜色反馈。  
修改后的结果：社区详情既可阅读灵感，也可直接理解和复用完整路线。  
用户预期：看到一条真实可执行的行程，而不是一张照片。  
优先级：P0

### STEP 10｜我的 / 设置

问题编号：P0-17、P1-16  
页面：我的、设置  
问题类型：Safe Area、Navigation、Content Density  
当前问题：我的页面底部导航仍会透出图片；封面与系统栏距离需统一；设置页虽已有社区地图显示开关，但没有在关闭后立即给用户明确的地图替代状态。  
为什么是问题：固定导航覆盖内容，用户误以为图片属于导航；设置的影响范围不够直观。  
用户操作步骤：我的 → 下拉到内容末尾 → 设置 → 关闭社区回放显示地图 → 再打开社区内容。  
当前结果：开关可用且不影响自己的行程地图；我的页面仍有底部图片泄漏。  
修改方案：Tab Bar 使用不透明白底、独立层叠上下文和左右安全边距；页面统一预留 TabBarHeight + SafeAreaBottom + 16；设置开关下方保留“只影响社区，行程地图始终保留”的解释，并在回放中显示稳定占位内容。  
修改后的结果：导航不再透图，开关的影响可预测。  
用户预期：我的内容和设置不会被系统 UI 覆盖。  
优先级：P0

## Phase 0 结论与进入执行阶段的门槛

本轮真实走查没有发现阻断主流程的路由错误；发现的核心问题集中在系统安全区、底部遮挡、地图初始化、Bot 统一性、社区详情信息完整度、酒店费用和导航视觉。以上记录构成后续执行的唯一验收基线。

执行顺序：

1. Foundation：状态栏图形化、Safe Area、402×874、单一滚动容器、Tab 不透明与底部安全间距。
2. Home/City：参考 splash、首页密度、城市 Medium Sheet、全局城市同步、Route Tab 图标。
3. Bot/Map：统一多表情 Bot、低噪声地图、稳定初始化与 segment camera、真实费用。
4. Community/Profile：具体行程列表、较轻复用 CTA、地图加载占位、封面与我的页面底部安全区。
5. 全链路回归：从启动重新走完本文件 STEP 01–10，并运行 typecheck、unit、build、E2E 与 402×874 截图检查。

只有完成第 5 步并确认无 Console Error、无横向滚动条、无内容被 Tab 遮挡，才算本轮完成。

## Phase 1 执行与 Phase 2 全链路复测

审计完成后才进入执行阶段。本轮实际修改范围：

- Foundation：状态栏改为 `9:41 + Dynamic Island + Signal/Wi‑Fi/Battery` 图形；展示壳固定 402 × 874；嵌入式页面使用单一滚动容器；Tab Bar 与详情操作条使用不透明白底、窄边距和安全区延伸，避免照片穿透。
- Home/City：启动覆盖页显示走走品牌标志约 2 秒后自动进入首页；动态行程改为“正在进行 / 上海 · Day 1 / 下一站 · 武康路 · 09:30”；同城推荐随 `city` 更新；城市 Sheet 选择一次即可同步首页、社区和行程。
- Navigation：行程 Tab 改为 Route 语义图标，选中为黑色、其余为中性灰；所有 Tab 保留 44px 触控区域与 pressed 缩放。
- Map/Bot：高德 Key 存在时继续使用 AMap JS API 2.0；无 Key 的本地 fallback 改为 Esri Canvas Light Gray Base + Reference，避免 CARTO API-key 水印；地图约 360px、只在初始化 Fit 全程，Bot 使用透明 Bloub SVG 状态并沿路线插值移动。
- Trip/Cost：行程头部改为“上海 · 3天2晚 / Day 1 · 正在进行”；补齐今日行程、预算与酒店参考价（上海静安酒店 ¥980），继续按钮即时切换暂停并保留地图。
- Community/Profile：社区详情增加具体行程清单（时间、停留、交通、费用）；复用 CTA 缩小；社区回放地图提供加载状态且支持设置开关；我的封面整面可点击更换。
